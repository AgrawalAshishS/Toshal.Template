Processor

class in Toshal.Template, assembly Toshal.Template

Turns parsed tokens into text. The data comes from five provider delegates that you set: one for each kind of tag that needs data. The processor does not read properties by reflection; your providers decide what each name means.

Remarks

Warning: when a provider is not set, its tags are skipped without an error. An IF block (with its ELSE) is skipped when ConditionValueProvider is null, a FOREACH block (with its NORECORD) when LoopValueProvider is null, and so on. A <%=name%> still writes a SET variable of that name when there is one.

The processor keeps no state between calls other than the provider properties, so one instance can process many templates, also from many threads at once.

Warning: to save allocations, one call of Process reuses one TokenArgs for all value and WITH tags and one ConditionArgs for all IF and ELSEIF tags. An args object is valid only while your provider runs; do not keep it.

Example

var processor = new Processor
{
    TokenValueProvider = args => args.Name == "name" ? ((Customer)args.Context!).Name : null,
    ConditionValueProvider = args => args.Name == "vip" && ((Customer)args.Context!).IsVip,
};
string text = processor.Process(new ProcessorArgs(tokens) { Context = customer }).ToString();

Parameters

Returns

A new StringBuilder with the text.

Exceptions

ArgumentNullException
args is null.
InvalidOperationException
The tokens hold a ReuseForEachToken made by hand that is not linked to a FOREACH. Tokens from Parse are always linked.

Remarks

Exceptions thrown by your providers are not caught; they reach the caller.

Example

StringBuilder text = processor.Process(new ProcessorArgs(tokens) { Context = order });
File.WriteAllText("order.txt", text.ToString());
void Process(ProcessorArgs args, StringBuilder output)

Processes the tokens with the given top context and appends the text to a builder you give. Reuse one builder (call Clear between runs) to avoid a new builder, its growth and the copy of ToString() for every run.

Parameters

args
The tokens and the top context.
output
The builder to append to. Text already in it stays.

Exceptions

ArgumentNullException
args or output is null.
InvalidOperationException
The tokens hold a ReuseForEachToken made by hand that is not linked to a FOREACH. Tokens from Parse are always linked.

Remarks

<%REMOVE_PREVIOUS n%> and <%REMOVE_PREVIOUS_NEW_LINE%> remove only text that this call wrote, never text that was in output before the call.

Exceptions thrown by your providers are not caught; they reach the caller. The text written before the exception stays in output.

Example

var output = new StringBuilder();
foreach (var order in orders)
{
    output.Clear();
    processor.Process(new ProcessorArgs(tokens) { Context = order }, output);
    writer.Write(output);   // TextWriter.Write(StringBuilder) copies no string
}
